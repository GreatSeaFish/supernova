# 传球升级与验证

本次改动基于 `bd7fc89`（包含已有传球优化的 main），在特性分支开发。

## 改动

1. **出球时机与截球风险**：球的飞行周期和对手可移动周期分开计算；两脚、三脚出球分别给对手增加 1、2 个准备周期，包括惯性位置、冲刺能力和转身后的到达判断。准备阶段仍使用固定出球点近似，并不模拟完整踢球序列。快速候选失败后继续检查较慢候选，避免遗漏因减少准备触球而更安全的选择。
2. **接球合法性**：同时使用防线、球的位置和中线判断越位，允许齐线和球后回传；正常比赛中额外检查接球人在多脚出球准备期间的惯性移动。过滤 ghost 接球人，执行时复查当前越位状态。此预测不包含未来主动冲刺和防线移动。
3. **执行与控球安全**：传播一脚出球的失败结果；一脚出球能力不足计划速度的 96% 时放弃该动作，避免低速球沿用高速球的安全判断。多脚出球遵守计划脚数（最多三脚）；SmartKick 失败时保留其已安排的控球动作，不发送传球通知。接球信息陈旧且对手逼近时不再原地等观察。控球候选同时检查第一周期和第二周期的抢球风险，修复对手已可抢球时仍保留“安全”评分的问题。
4. **传球收益**：接球空间在 2–6 米之间线性增加奖励，6 米以上封顶；奖励乘以 `1 / (1 + 0.04 * spendTime)`，偏向相同空间下更快的传递。空间使用最多 10 周期的对手惯性预测，并按观测陈旧度扣除至多 1 米。仍允许最多 5 米的回传获得奖励，最高奖励保持 8 分。
5. **持续验证**：新增不依赖 librcsc 的 C++ 场景测试；修正完整构建工作流原先只监听 `cyrus2d` 的配置，覆盖 main、codex 和 feature 分支及面向 main 的 PR。

## 本地验证

```sh
cmake -S tests -B build/pass-tests
cmake --build build/pass-tests
ctest --test-dir build/pass-tests --output-on-failure
```

测试包含球后回传、齐线、己方半场、准备期间跨越防线，以及奖励的压力阈值连续性、空间排序、耗时排序和有界性。

修改过的四个 C++ 源文件已使用 GNU C++17 和仓库工作流固定的 librcsc 提交 `19175f339dcb5c3f61b56a8c1bff5345109f22ef` 通过语法检查。这不是完整链接或比赛验证；GitHub 的 CMake 工作流负责 Linux 完整构建。

## 合并前比赛评估

尚未运行 100 场对战，不能据此声称传球成功率或胜率提升。按仓库约定，测试前先同步最新 main，然后固定服务器参数、对手版本与种子集合，对 main 和本分支分别进行同条件对战。

建议记录胜/平/负、净胜球、传球尝试与成功率、传球后短时间内丢球次数、越位次数、对手半场成功接球次数及每周期决策耗时（尤其关注继续枚举慢速候选的开销）。成功传球需按实际队友获得球权统计，不能仅以已发送的传球通知计数。

本地环境没有可用的 RoboCup 比赛服务器，场景测试未覆盖完整世界模型或动作队列。合并 main 前仍需比赛评估及执行路径的仿真验证。
